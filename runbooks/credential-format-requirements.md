# Credential Format Requirements

**Document Purpose**: Define password policies, API key formats, and character restrictions for all services in the homelab SSOT to prevent lockouts during credential rotation.

**Last Updated**: 2026-01-03
**Session**: Ralph maintenance - credential-format-research

## Quick Reference: Safe Password Generation

### Recommended Safe Character Set

For maximum compatibility across all services, use this character set:

```
Allowed: A-Z a-z 0-9 ! @ # $ % ^ & * ( ) _ + - = [ ] { } | ; : , . < > ?
Avoid:   ` ~ " ' \ / @ (in usernames) : (in connection strings)
```

### Problematic Characters by Context

| Character | Issue Context | Affected Services |
|-----------|---------------|-------------------|
| `$` | Shell variable expansion | All CLI-based operations |
| `!` | Bash history expansion | Shell commands, some configs |
| `'` `"` | Quote conflicts | YAML configs, shell commands |
| `\` | Escape sequences | PostgreSQL, shell, YAML |
| `@` | URL parsing (user:pass@host) | Connection strings, PostgreSQL |
| `:` | URL parsing (host:port) | Connection strings |
| `/` | URL path separator | PostgreSQL connection strings |
| `?` | Query string delimiter | PostgreSQL URLs |
| `%` | URL encoding prefix | Must be encoded as %25 |
| `#` | Comments in config files | YAML, shell scripts |

### Harbor

| Field | Min Length | Max Length | Special Chars | Hash Algorithm |
|-------|------------|------------|---------------|----------------|
| `admin_password` | 8 | 128 | Requires 1 uppercase | PBKDF2-SHA256 |
| `database_password` | N/A | N/A | URL-safe | PostgreSQL |

**CRITICAL - HASH ALGORITHM**:

```
Algorithm: PBKDF2-SHA256
Iterations: 4096
Key Length: 16 bytes (32 hex characters)
Format: sha256(salt + password) - computed via pbkdf2.Key()
```

**Python hash generation**:

```python
import hashlib
dk = hashlib.pbkdf2_hmac('sha256', password.encode(), salt.encode(), 4096, 16)
hash = dk.hex()  # 32 character hex string
```

**Requirements**:

- At least 1 uppercase character
- Min ~8 characters (common practice)

**Sources**: [Harbor Docs](https://goharbor.io/docs/2.0.0/install-config/configure-yml-file/)

## SSO/OIDC Client Secrets

| Field | Recommended Length | Format | Notes |
|-------|-------------------|--------|-------|
| `client_secret` | 32-64 chars | Alphanumeric | URL-safe for client_secret_basic |

**Best Practices**:

- Use 256+ bits of entropy (32+ bytes)
- Alphanumeric only for maximum compatibility
- When using special chars, make sure URL encoding for `client_secret_basic`
- Prefer `client_secret_jwt` to avoid sending secret over network

**Generation**:

```bash
openssl rand -base64 32 | tr -d '/+=' | head -c 32
```

**Sources**: [OAuth 2.0 Simplified](https://www.oauth.com/oauth2-servers/client-registration/client-id-secret/)

## PostgreSQL Connection Strings

**General PostgreSQL password rules**:

- All printable characters technically allowed
- But connection strings have parsing issues

**MUST ENCODE these characters**:

| Character | Encoding |
|-----------|----------|
| `@` | `%40` |
| `:` | `%3A` |
| `/` | `%2F` |
| `?` | `%3F` |
| `#` | `%23` |
| `%` | `%25` |

**Best Practice**:

```python
from urllib.parse import quote
encoded_password = quote(password, safe='')
```

**Recommendation**: Use only `A-Za-z0-9!_-` for PostgreSQL passwords to avoid encoding issues.

**Sources**: [PostgreSQL Connection Strings](https://www.w3tutorials.net/blog/how-to-handle-special-characters-in-the-password-of-a-postgresql-url-connection-string/)

## Summary: Safe Password Generation Rules

### Universal Safe Character Set

For rotation across ALL services, use ONLY:

```
Characters: A-Z a-z 0-9
Safe Specials: ! @ # % ^ & * _ + - = . ,
Length: 24 characters (meets all minimums)
```

### Per-Service Adjustments

| Service | Additional Restrictions |
|---------|------------------------|
| MikroTik | Avoid `$`, max 28 chars |
| WireGuard | Alphanumeric ONLY |
| Harbor | Must include 1 uppercase |
| NetBox | Must include letters AND numbers |
| Grafana | Avoid `( )` in config files |
| UniFi | Avoid `"` |
| AdGuard | Avoid `!` |
| GitLab | Avoid `!` (escape issues) |
| PostgreSQL | Avoid `@ : / ? # %` or URL-encode |

### Recommended Password Generator Settings

```yaml
password_generation:
  default:
    length: 24
    charset: "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789"
    # No special chars by default - safest

  with_special:
    length: 24
    charset: "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#%^&*_+-=.,"
    # Excludes: $ ' " \ / : ; < > ? { } [ ] ( ) ` ~ |

  mikrotik_safe:
    length: 24  # Max ~28
    charset: "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789"

  wireguard_safe:
    length: 24
    charset: "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789"

  postgresql_safe:
    length: 32
    charset: "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!_-"
```

## Validation Before Rotation

Before rotating any credential, verify:

1. **Length compliance**: Meets minimum for target service
2. **Character set compliance**: No forbidden characters
3. **Hash algorithm known**: Can regenerate if direct DB update needed
4. **API available**: Can apply without manual intervention
5. **Rollback path**: Backup current credential before change
